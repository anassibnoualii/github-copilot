## What is Copilot Edits?

Copilot Edits is a multi-file editing mode that lets you make coordinated changes across multiple files from a single prompt. Unlike Chat, which shows suggestions as text, Edits directly modifies your files and shows a diff review.

<Callout variant="info" label="Edits vs Chat">
Use Chat when you want to ask questions and understand code. Use Edits when you want Copilot to actually make changes across one or more files.
</Callout>

## Opening Copilot Edits

In VS Code, open Copilot Edits from:
- The Copilot menu → **Open Copilot Edits**
- Command Palette: `Copilot: Open Edits`

## The Working Set

The working set is the list of files Copilot is allowed to edit. You add files explicitly:

1. Click **Add Files** in the Edits panel
2. Select files from your workspace
3. Write your prompt — Copilot modifies only the files in your working set

<Callout variant="tip" label="Start small">
Add only the files relevant to your change. Copilot performs better with a focused working set than with every file in your project.
</Callout>

## Reviewing Changes

After Copilot makes edits, you review each change:

| Action | What it does |
|--------|-------------|
| **Accept All** | Accept all changes across all files |
| **Reject All** | Discard all changes |
| **Accept File** | Accept changes in one specific file |
| **Accept Hunk** | Accept a single block of changes |
| **Reject Hunk** | Discard a specific change while keeping others |

## Edit History

Copilot Edits keeps a history of edit sessions. You can:
- Navigate back to previous edit states
- Undo the last edit session
- Compare before/after for each session

## Keyboard Shortcuts in the Review Flow

Navigating and acting on hunks is faster with keyboard shortcuts than clicking through the diff UI:

| Shortcut | Action |
|---|---|
| Tab | Move to next changed hunk |
| Shift+Tab | Move to previous hunk |
| Y | Accept current hunk |
| N | Reject current hunk |
| Cmd+Enter / Ctrl+Enter | Accept all changes |
| Escape | Close the diff view |

Mastering these shortcuts turns hunk review from a slow click-through into a rapid keyboard-driven workflow — especially useful when reviewing changes across a dozen files.

## Working Set Limits & Best Practices

Copilot Edits is powerful but has practical limits:

- **Max ~20 files** in the working set — beyond this, performance degrades and edit quality drops noticeably
- Edits cannot touch **binary files, images, or compiled output**
- **Generated files** (`dist/`, `build/`) should always be excluded — Copilot may produce inconsistent output if it tries to edit generated artifacts
- If Copilot proposes changes to a file you didn't intend to include, remove it from the working set and re-run

<Callout variant="tip" label="Split large tasks">
If you need to touch more than 10 files, split the task into smaller edit sessions with logical groupings. For example: first session handles the data layer, second session handles the API layer, third handles the UI.
</Callout>

## A Multi-File Example Walkthrough

Here is a realistic Copilot Edits workflow for a backend middleware task.

**Task:** "Add request logging middleware and update all route files to use it"

**Working set:**
- `src/middleware/logger.ts` (new file — Copilot will create it)
- `src/routes/users.ts`
- `src/routes/posts.ts`
- `src/app.ts`

**What happens:**

Copilot creates `logger.ts` from scratch, then patches all three existing files — adding the import and wiring the middleware into each router — in a single edit session. All four files appear in the diff view simultaneously.

**Reviewing the diff:**

- `logger.ts` — new file, looks correct → **Accept File**
- `src/routes/users.ts` — middleware import and `router.use(logger)` added → **Accept File**
- `src/routes/posts.ts` — same pattern → **Accept File**
- `src/app.ts` — Copilot added `app.use(logger)` but placed it after the route registrations → **Reject Hunk** (you'll add it manually in the right position)

This is the core advantage of Copilot Edits over Chat: you can accept 90% of a multi-file change in seconds, then correct only the specific hunk that's wrong — without reverting everything or starting over.

## Best Practices

```bash
# Good: Focused, single-concern prompt
"Add error handling to all functions in src/services/userService.ts"

# Good: Clear scope
"Convert the callback-style database queries in src/models/ to async/await"

# Avoid: Too broad
"Improve the entire codebase"
```

<Callout variant="success" label="Iterative edits work best">
Break large changes into multiple smaller edit sessions. Review and accept each batch before starting the next one.
</Callout>
