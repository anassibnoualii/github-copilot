## The New Copilot CLI

The new GitHub Copilot CLI is a full agentic terminal assistant — not just a command suggester. It can read files, run commands, write code, and complete complex multi-step tasks directly in your terminal.

```bash
# Install globally via npm (Node.js 22+ required)
npm install -g @github/copilot

# Or via Homebrew (macOS/Linux)
brew install copilot-cli

# Or via winget (Windows)
winget install GitHub.Copilot
```

## Starting a Session

```bash
copilot
```

This opens an interactive session where you can describe tasks in natural language. Copilot reads your current directory, understands the project, and can take actions.

## Normal vs Autopilot Mode

The CLI has two operating modes:

| Mode | Behaviour |
|------|-----------|
| **Normal** | Copilot proposes a plan and asks approval before each step |
| **Autopilot** | Copilot executes the full task autonomously without step-by-step approval |

Press **Shift+Tab** to toggle between modes within an active session.

<Callout variant="warning" label="Use Autopilot carefully">
Autopilot mode will execute file changes and run commands without asking at each step. Make sure you're in a clean git state before using it for large tasks.
</Callout>

## Slash Commands in the CLI

| Command | What it does |
|---------|-------------|
| `/model` | Switch the AI model for this session |
| `/resume` | Resume a previous session by ID |
| `& <task>` | Offload a task to a cloud-hosted agent (runs in background) |

## Security Model

The Copilot CLI is designed to be safe by default:

- Only reads files in your **current working directory** (won't access parent directories)
- Shows you all proposed file changes before applying them in Normal mode
- Requires explicit approval for terminal commands that modify state
- Never stores your files or code on GitHub servers

<Callout variant="tip" label="Best practices">
Run `copilot` from your project root so it has full access to your project files. Use Normal mode for unfamiliar tasks and Autopilot for well-understood, repetitive work.
</Callout>

## Piping Output into Copilot

Standard Unix piping works seamlessly with the Copilot CLI. Copilot reads stdin as additional context, making it straightforward to feed terminal output directly into your prompt.

```bash
git diff | copilot "explain these changes and flag risky ones"

npm test 2>&1 | copilot "fix the failures"

cat error.log | copilot "what is causing this error?"
```

This is particularly useful after a failed CI run — pipe the test output directly to Copilot and ask it to fix the failures without copy-pasting anything manually.

## Inspecting Capabilities

If you're unsure what's available, two commands give you a full picture:

```bash
copilot --help
```

This prints all top-level flags and subcommands before starting a session.

Inside an active session, type:

```bash
/help
```

This lists every slash command available in the current session, including any model-specific capabilities. Use it whenever you start a new session or switch models.

## Error Recovery Patterns

Copilot makes mistakes. Having a recovery plan before it happens is important, especially in Autopilot mode.

**Before large Autopilot tasks — stash your changes:**

```bash
git stash
copilot
# run the task in Autopilot
# review results, then either:
git stash pop   # restore your original changes if Copilot made a mess
```

**Resume an interrupted session:**

If a session was cut off (network drop, accidental close), use `/resume` followed by the session ID shown in the output history. Copilot will reload the context and continue from where it left off.

**Correcting mistakes inline:**

Don't restart the session. Describe what went wrong directly:

```
› That's wrong because you added the middleware after the route definitions — it needs to run before them. Move app.use(authMiddleware) to line 12.
```

Being specific about why something is wrong — not just that it is wrong — gives Copilot enough context to make the right correction the first time.

## A Real Multi-Step Session Example

Here is a realistic terminal session showing how Normal mode, inline corrections, model switching, and background tasks work together:

```bash
$ copilot
› Set up authentication middleware for this Express app with JWT

# Copilot reads the project files, proposes a plan:
# - install jsonwebtoken and @types/jsonwebtoken
# - create src/middleware/auth.ts
# - update src/app.ts to use the middleware
# User reviews the plan and approves each step

› The token should expire in 24h not 1h

# Copilot opens src/middleware/auth.ts, finds the expiresIn value,
# changes '1h' to '24h', shows the diff, user approves

› /model
# Copilot lists available models; user switches to a different one

› & Write integration tests for the auth routes in the background
# Task is offloaded to a cloud agent
# User continues working; gets a notification when tests are ready
```

The `&` prefix is the key to parallelism — send long-running tasks (writing tests, generating docs, refactoring large files) to a background cloud agent while you keep working in the foreground.
