## What is `.github/copilot-instructions.md`?

This file tells GitHub Copilot about your project — its stack, conventions, and rules. Copilot reads it automatically before every chat session and code generation request. It is IDE-agnostic: the same file works in IntelliJ IDEA, the Copilot CLI, and GitHub.com.

Place the file at:

```
your-project/
└── .github/
    └── copilot-instructions.md
```

Commit it to version control. Every developer who clones the repo gets consistent Copilot behavior with zero additional setup.

## Complete Example for a Spring Boot Project

```markdown
# Copilot Instructions

## Stack
- Java 21 (use records, sealed classes, and pattern matching where appropriate)
- Spring Boot 3.x with Maven
- Spring Data JPA + PostgreSQL
- JUnit 5, Mockito, Testcontainers for integration tests
- MapStruct for DTO mapping
- Lombok: @Getter, @Builder, @RequiredArgsConstructor, @Slf4j only

## Code Style
- Google Java Style Guide, 2-space indentation
- Constructor injection only — no @Autowired on fields
- Return Optional<T> instead of null
- Use @Transactional on service methods that write to the database
- Add @Transactional(readOnly = true) on service methods that only read

## Architecture
- Controllers are thin: validate input, call a service, return a response
- Services own business logic and transactions
- Repositories extend JpaRepository — do not add business logic here
- Never expose JPA entities in API responses — use DTOs with MapStruct
- Errors: throw custom exceptions extending RuntimeException from com.example.exceptions

## Tests
- Naming: methodName_scenario_expectedBehavior
- Unit tests mock dependencies with Mockito
- Integration tests in src/test/java/integration/ use @SpringBootTest + Testcontainers
- Every public service method needs at least one unit test

## Build Commands
- ./mvnw compile — compile only
- ./mvnw test — run all tests
- ./mvnw verify — tests + integration tests
- ./mvnw spring-boot:run — start the app locally

## Commit Format
type(scope): short description
Types: feat, fix, refactor, test, docs, chore
```

## What to Include — and What to Skip

**Include things Copilot would get wrong without your context:**
- Your injection style (constructor, not field `@Autowired`)
- Your null handling approach (`Optional<T>`, not `null` returns)
- Your naming conventions that deviate from Java defaults
- Which layers own which responsibilities
- Which annotations are allowed vs forbidden
- Build commands Copilot can run to verify its own changes

**Skip generic advice that wastes tokens:**
- "Write clean code", "follow SOLID", "use meaningful names" — Copilot already knows these
- Language basics and standard library usage
- Framework docs already in Copilot's training data

Instructions over 500 lines cause Copilot to silently truncate context. Test whether your instructions are being applied by asking Copilot to repeat back key rules: `"What injection style should I use in this project?"`

## Per-File Instructions for Large Projects

For large projects or monorepos, add scoped instruction files in `.github/instructions/`:

```
.github/
├── copilot-instructions.md             ← applies to everything
└── instructions/
    ├── tests.instructions.md           ← only test files
    ├── api.instructions.md             ← only controller files
    └── services/payments.instructions.md  ← only the payments service
```

Each file uses a YAML front-matter `applyTo` glob:

```markdown
---
applyTo: "src/test/**"
---

All test classes must use @ExtendWith(MockitoExtension.class).
Never use @SpringBootTest in unit tests.
Use Testcontainers only in src/test/java/integration/.
```

**Monorepo pattern:** Keep the root `copilot-instructions.md` minimal (project overview, shared conventions). Put service-specific rules in scoped files:

```markdown
---
applyTo: "services/payments/**"
---

Payments service uses Stripe SDK v12. Always pass idempotency keys to Stripe API calls.
Never log full card numbers — mask to last 4 digits only.
```

## Instruction Load Order

| File | When it applies |
|------|----------------|
| `.github/copilot-instructions.md` | Every interaction in this repo |
| `.github/instructions/*.instructions.md` | Only files matching the `applyTo` glob |

All matching files are applied together — they are additive, not exclusive.
